## 1. Что делали в этой сессии
- Нода F переименована: `Prompt logistics — MODEL` → **`Prompt logistics — SYS`**
  (`NODE_DISPLAY_NAME_MAPPINGS`, докстринг, DESCRIPTION, tooltips выходов,
  `SPECIFICATION.md`, `README.md`). Класс/ключ `PromptLogisticsModel` НЕ менялся —
  старые воркфлоу не ломаются.
- Двум переключателям добавлено «вкл», чтобы отличать от входов:
  `Мастер-стиль: вкл` (`style_prompt`), `Дополн. промпт: вкл` (`use_int`).
  Входы остались `Мастер-стиль` / `Дополн. промпт`; подтянуты все tooltips,
  DESCRIPTION, таблицы/легенда `SPECIFICATION.md`, `README.md`.
- По решению пользователя: английская версия не нужна; `sys prompt mod` /
  `sys prompt plus` / `sys use LLM` оставлены как есть.
- Приведена в соответствие **живая проба**: она держала старый порядок слотов
  (0 = прямой, 1 = LLM) и старые подписи — обновлена на новый контракт
  (0 = `Промпт в LLM`, 1 = `sys prompt mod`), иначе упала бы на живом сервере.
- Проверки: тест 138 → **140**, аудит 91 → **94**; 6 мутаций RED (шестая вскрыла
  слепую проверку README — детектор добавлен и мутирован).
- Коммит `e0e3fda`, запушен; синхронизировано 3 файла в рабочую копию.

## 2. Итоговое состояние кода
- Подписи S: входы `Основной промпт` / `Мастер-стиль` / `Дополн. промпт`;
  переключатели `LLM промпт` / `Мастер-стиль: вкл` / `Мастер-стиль в LLM` /
  `Дополн. промпт: вкл` / `Дополн. промпт в LLM`.
- `RETURN_NAMES` S = (`Промпт в LLM`, `sys prompt mod`, `sys prompt plus`,
  `sys use LLM`); F-входы названы теми же строками, F-выход — `Итоговый промпт`.
- F: имя в меню `Prompt logistics — SYS`, `DESCRIPTION` объясняет ленивость
  `Промпт из LLM`; `finalize` (~223) возвращает `""`, если база пустая.
- `compose()` (~130): `llm` = осн + дополн. (`use_int and int_in_llm`) +
  мастер-стиль (`style_prompt and style_in_llm`); `direct` = осн + дополн.
  (`use_int`) + мастер-стиль (`style_prompt`); `suffix` — только при
  `llm_prompt` и `not ..._in_llm`.
- `check_lazy_status` (~207): `[]` без реальной связи `[id, slot]`.
- Проверки: Python **140**, аудит **94**, `check.py` 0 провалов (1 warn —
  предохранитель git), живая проба 48 (после рестарта).

## 3. Проблемы, которые встречались (и как решали)
- Слепая замена `"display_name"` попала во входы (`master`, `int_prompt`) вместо
  переключателей. Лечение: правка по номерам строк с `assert` на старое значение.
- heredoc в git-bash схлопывает `\` → блоки с `\n`/regex править только
  edit-tool; при кириллице в stdout — `PYTHONIOENCODING=utf-8`.
- Мутация «README без „вкл“» осталась ЗЕЛЁНОЙ: проверка искала слова во всём
  файле, а они есть в других местах. Детектор заякорен на строку
  `Переключатели: …` → мутация стала RED.
- Проба не была обновлена при перестановке слотов (дыра прошлой сессии) —
  обнаружена теперь, исправлена вместе с подписями.

## 4. Что важно не сломать
- Цикл `S → LLM → S` невозможен (`dependency_cycle`, HTTP 400): разрыв — нода F.
- `style_prompt`/`use_int` — главные выключатели; `style_in_llm`/`int_in_llm` —
  только маршруты; `suffix` никогда не содержит часть, ушедшую в LLM.
- `sys prompt mod` всегда содержит дополн. промпт при включённом выключателе.
- `check_lazy_status` обязан молчать без реальной связи.
- Keys входов (`prompt`/`master`/`int_prompt`/…) не менялись; перестановка
  слотов (877de2a) ломает провода в старых воркфлоу.
- `display_name` — единственный источник подписей; JS/`locales` нет.
- Синхронизация: `python sync.py Prompt_Logistics` + рестарт ComfyUI.
